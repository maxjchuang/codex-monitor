# Codex 监控

在 DSH 左侧栏直接查看并驱动本机 **Codex 桌面版**（ChatGPT.app 内置的 Codex）。

## 它解决什么问题

Codex 桌面版在后台跑任务时，你看不到它在做什么，也不知道它是不是卡在等你回答。
切窗口去翻会话很打断手头的事。这个插件把状态搬进 DSH：

- 哪些会话正在跑、跑到哪一步
- 哪个会话正在**等你拍板**（会显示它的提问和选项）
- 直接给它派活，不用切窗口

## 怎么用

1. 左侧栏点击 **Codex 监控**，进入整页。
2. 页面分成两栏：**左边是会话列表**，按**项目（文件夹）分组**，和 Codex 自己的侧栏一样；
   **右边是这个会话的聊天窗口**。
   - 分组不会打乱优先级：**有会话等你回答的项目排最前**，其次是有任务在跑的项目。
   - 项目标题右边的小徽标告诉你这个项目里有几个在等你、几个在跑，末尾数字是会话总数。
   - 点项目标题可以整组折叠；单个项目会话很多时，默认只显示最紧急的 5 个，
     点「展开显示 N 个」看全部（比如 `base-ui-component-lib` 可能有 20 多个）。
3. 点左边任意一行，右边立刻换成那段对话。排版跟 DSH 自己的对话一致：**你说的话靠右、带浅色气泡**，
   **Codex 说的话是流式正文、不加气泡**，一段话就是一段话。
   跑命令之类的动作显示成等宽小字的命令行，连续很多步会压成「执行命令 … 共 63 步」。
   Codex 在等你拍板时，会单独显示一张浅色提问卡。
4. 底部输入框直接给它派活。Codex 会把这条作为新的一轮追加进去。

打开面板时会**自动选中排最前那个会话**，不用先点一下才看到内容。
对话只取最近一段（会话很长时窗口顶部会说明只显示最近 N 条）。

右侧聊天窗口只在有人看的时候轮询：有任务在跑时 5 秒一次，空闲时 30 秒一次，
页面切到后台就停。往上翻看历史时不会被新消息拽回底部。

左侧栏图标右上角出现红点时，说明有会话正在等你回答——**切到别的页面也一直可见**，
因为这个红点的样式是注入到页面 `document.head` 的，不随面板卸载而消失。

读屏软件看不到图标本身（侧栏把图标子树标记为 `aria-hidden`），所以等待数量同时写进了
这一行的无障碍标签，例如「Codex 监控（1 个等你回答）」。

## 派活的语义

**发送不会打断正在跑的任务。** 它作为新的一轮追加到该会话末尾，Codex 处理完当前任务后才会看到。
要开全新会话，请用命令行 `codex_ctl.py new`。

**发送失败会保留你输入的内容。** 界面要等 Codex 真正接受了这一轮才报成功；如果被拒绝
（例如会话 id 不存在），会显示 Codex 返回的错误，草稿留在输入框里，不会凭空丢掉。

**同一个会话同一时刻只能有一个写入者。** 面板开着时，命令行对同一个会话 `send` 会报
`already has an active writer`，改用面板或先关掉它。

## 它不会替你回答

插件会把 Codex 的提问和选项**呈现**给你，但不会自动选择或回复。
点击选项只是把文字填进输入框，仍然需要你自己按发送。

## 数据来源

- 会话列表、轮次状态、最近动作：读 `~/.codex/` 下的 SQLite（`state_5.sqlite`、`thread_history_1.sqlite`）
- 派活与提问：通过 `codex app-server` 的 JSON-RPC

所有逻辑都在 `codex_ctl.py` 里，命令行和这个界面共用同一份实现，不会出现两边状态不一致。

## 已知限制

- **只支持本机**。不涉及 Codex Cloud 或 ChatGPT 网页版。
- **状态判断有明确优先级**，不是单看某个字段：
  1. 有待回答问题 → 「等你回答」（Codex 确实停下来了）
  2. `turn.status` 已是终态（`completed`/`failed`）→ 直接采信，心跳不能覆盖
  3. `inProgress` → 「正在跑」
  4. 只有 `interrupted`/未知才回落到最近活动心跳（300 秒窗口）

  之所以要这个顺序：Codex 把正在跑的轮次持久化成 `interrupted`，而 `inProgress` 标记又会滞后几分钟；
  反过来，几乎所有已完成的轮次最后一条动作都发生在心跳窗口内。任何单一字段都会误判。
- **派活依赖长驻进程**。`app-server` 随派活进程一起退出时，Codex 会把在飞的轮次标成 `interrupted`，
  任务实际上没执行。插件因此托管一个长驻的 `codex_ctl.py serve`，全程复用同一个 `app-server`。
- **不支持停止任务**。命令行也没有这个能力。
- 需要本机有 `python3`。找不到时页面会明确提示，可用 `CODEX_MONITOR_PYTHON` 指定路径。
- 独立启动的 `app-server` 看不到桌面版正在跑的轮次，这是 Codex 自身的限制，状态因此依赖 SQLite 心跳。

## 故障排查

| 现象 | 原因 |
|---|---|
| 页面提示找不到 python3 | 装 Python 3，或设 `CODEX_MONITOR_PYTHON` |
| 提示读不到会话 | 确认 `~/.codex` 存在，且桌面版至少跑过一次 |
| 状态显示「已停下」但实际在跑 | 静默超过 300 秒窗口，等 Codex 写下一条动作即可 |
| 派活后任务没执行，轮次只跑了几十毫秒 | app-server 随进程退出了；确认走的是长驻 `serve`，而不是每次新起进程 |
| 命令行派活报 `already has an active writer` | 面板正持有该会话的写入权，改用面板或先关掉 |
| 红点不显示 | 确认面板至少加载过一次（样式在首次加载时注入），之后即可常驻 |
